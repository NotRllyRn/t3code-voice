# Experimental Voice releases and upstream automation

This fork uses `U-voice.R`: `U` is a pinned, stable upstream version and `R` is a positive Voice revision. For example, `0.1.9-voice.1` → `0.1.9-voice.2` → `0.1.10-voice.1`. The pin and channel policy live in [`forkIdentity.ts`](../../packages/shared/src/forkIdentity.ts). Voice versions are SemVer prereleases, not build metadata. The current experimental channel requires GitHub `prerelease: true`; changing that policy needs a reviewed consumer compatibility change. It does not mean upstream stable releases belong in a Voice feed.

Only the exact installed `0.1.9-preview.20261116.1` preview is an allowed legacy current version. Desktop downloads are manual; the ARM64 DMG selector is not an Electron ZIP/feed updater. macOS ad-hoc signing is not Developer ID signing or notarization. This release targets macOS and its matching server/web client. Fork mobile/iOS work is deferred; upstream mobile source is retained.

## Build-only evidence, not publication

After human merge to `feature/codex-voice-stable`, `voice-build.yml` can build an explicit full source SHA that is an ancestor of that branch. All four existing release package manifests must already match the configured Voice version; the build does not rewrite source. The workflow defaults off behind `VOICE_BUILD_ENABLED` and the `voice-build` environment. Configure required human reviewers **before** enabling that variable; naming an environment alone creates no approval protection.

The lane builds Linux x64 server archives and macOS ARM64 DMG/ZIP artifacts afresh, with a smoke check for each. It retains workflow artifacts for 14 days, named with version, full source SHA and target. Each target carries `voice-release.json`, `SHA256SUMS`, and upstream notes followed by `## Voice Fork`. The descriptor records the source/upstream pins, registered database migration head, orchestration protocol version, final-byte SHA-256/size, target and experimental trust state. Per-target descriptors are build evidence, not a combined public release manifest or update feed. Publication would need a separately reviewed aggregation step that rejects mismatched versions/source pins, plus explicit approval. No release, tag, npm publication, deployment or installation runs here.

The inherited upstream release pipeline remains gated. This lane does not pass the inherited `--skip-build` flag, which the fork packager correctly refuses. Native build success, artifact retention, macOS trust, real installation/update and rollback must be evidenced separately; a checksum or successful unit test is not that proof. Hosted runner availability and macOS billing limits must be checked on the account.

## Signed upstream notification (not enabled)

`voice-upstream-watch.yml` polls GitHub's stable release API every six hours **only when installed on the default branch and enabled**. It can also be explicitly dispatched after that installation. It reads the accepted pin from the stable fork branch, independently resolves lightweight/annotated tags to a full SHA, checks ancestry, and signs a small JSON identity payload. There is no upstream webhook installation and no T3 polling fallback.

Before activation:

1. Review the coordinator contract and security boundary with the parent. Confirm the registered project has `scripts: []` and `autoPull: false`; no automatic setup or `.env` linking is allowed. Workers must use the explicit project and a separate worktree, never a default/root workspace.
2. Set up a **signed T3 webhook**, bound to a visible coordinator thread. Use `request_secret`'s private card for the user-chosen HMAC key; never put the key in chat, a command argument, a release payload or the repo. Configure the same key directly in GitHub's protected `voice-automation` environment as `VOICE_UPSTREAM_WEBHOOK_SECRET`. Do not invent a key. Keep `VOICE_UPSTREAM_WATCH_ENABLED` off.
3. Use the supported `schedule_task` API with `schedule: {type: "webhook", signature: {header: "x-hub-signature-256", encoding: "hex", prefix: "sha256=", secretRef}, maxDeliveryAgeMinutes: 5, dedupe: {replayKey: "{{body.tag}}:{{body.sha}}", coalesceKey: "{{body.tag}}:{{body.sha}}", coalesceWindowSeconds: 120}}`, `bindToCurrentThread: true`, and `enabled: false`. The secret reference is consumed once. The managed `webhookUrl` is the GitHub URL secret; if it is absent, T3 Connect remote access is required. Do not expose a local-only path or replace this with an unsigned webhook.
4. The coordinator must parse the request as untrusted data, verify it independently against GitHub again, then persist a claim **before** `t3_thread_launch`. Use the guard in `scripts/voice-upstream-coordinator.ts`; its prepared request explicitly names the project, `feature/codex-voice-stable`, a new worktree branch and `startFromOrigin: false`. Never execute release notes or use external text as worker instructions. This helper alone is not an installed coordinator service.
5. Attach durable deadline cancellation/reconciliation before any unattended run. The guard records one active launch, at most one launch in a rolling 24 hours, and a two-hour deadline. A recorded deadline is **not** a timer. A live supervisor must call `t3_thread_interrupt` at the deadline, cancel unfinished child work, confirm it stopped and release the claim only after human reconciliation. There is no configured hard dollar cap. Enabling unattended work requires a provider/account cap or explicit user acceptance of bounded-run spending risk.
6. In an isolated synthetic fixture project/worktree, prove valid signature → one visible thread, unsigned/bad signature → no thread, duplicate/stale/expired payload → no second thread, and actual deadline cancellation. Confirm worker setup creates no `.env` link and does not inherit production credentials. Observe the full delivery path and clean up the fixture. Offline fake-webhook tests do not replace this trial.
7. Only after parent approval of that evidence may a human install/enable the default-branch workflow, configure protected environments, set the URL/key secrets and enable the GitHub variable. Full Stop forbids this PR from pushing the default branch, merging, publishing or deploying.

The claim state directory must be owner-only (`0700`), outside the checkout and live T3 home. A crash/unknown launch stays claimed: inspect the returned thread and worktree before changing state, never age out a lock and retry a non-idempotent launch. Do not clear replay history to work around a failed run. Worker output is an early independently reviewed progress PR against the stable branch and a tested, mergeable handoff; never an automatic merge or deployment.

## Local checks

From `packages/shared`, run `vp test run --config ../../vite.config.ts src/voiceRelease.test.ts src/semver.test.ts`. From `scripts`, run `vp test run --config ../vite.config.ts voice-*.test.ts`. These checks use offline synthetic API/webhook/artifact fixtures. Run `vp run check:changed feature/codex-voice-stable` before pushing. No root dependency install or production state is needed for these checks.

# Experimental Voice releases and upstream automation

This fork uses `U-voice.R`: `U` is a pinned, stable upstream version and `R` is a positive Voice revision. For example, `0.1.9-voice.1` → `0.1.9-voice.2` → `0.1.10-voice.1`. The pin and channel policy live in [`forkIdentity.ts`](../../packages/shared/src/forkIdentity.ts). Voice versions are SemVer prereleases, not build metadata. The current experimental channel requires GitHub `prerelease: true`; changing that policy needs a reviewed consumer compatibility change. It does not mean upstream stable releases belong in a Voice feed.

Only the exact installed `0.1.9-preview.20261116.1` preview is an allowed legacy current version. Persistently signed macOS builds support native ZIP/feed updates through the Voice feed; the manual ARM64 DMG path remains available. Voice.6 was verified through pristine public .4 → .6 and local .5 → .6 upgrades. Each later release still needs its own packaged acceptance. Keychain requests were denied in those isolated fixtures, so encrypted credential continuity remains unverified. macOS private self-signing is not Apple-trusted Developer ID signing or notarization. This release targets macOS and its matching server/web client. Fork mobile/iOS work is deferred; upstream mobile source is retained.

## Build-only evidence, not publication

After a reviewed merge to the configured Voice integration branch, `voice-build.yml` accepts the exact merge SHA, PR number and reviewed head SHA. It verifies the merged PR identity and source ancestry in `VOICE_BUILD_BASE_BRANCH`; missing configuration fails closed. Register this workflow on the default branch and restrict the `voice-build` environment to that exact branch before enabling it. Set `VOICE_BUILD_ENABLED` and `VOICE_BUILD_BASE_BRANCH` in that environment only. All four release package manifests must match the configured Voice version; the build never rewrites source. Environment reviewers, if configured, make each build supervised. For this personal fork, the authorized subagent council reviews the exact head: every reviewer must score at least 9.2/10, with at most 8 rounds and no unresolved blockers. Relevant runnable checks must pass. Respect existing enforced GitHub protections without bypass; a separate GitHub reviewer account or app is not required. Do not add failing required checks merely to enable automation.

`Voice automation tests` runs on GitHub-hosted Ubuntu with a frozen filtered dependency install. It covers stable-release validation, coordinator claims, signed webhook/replay behavior and build preflight. Require this check only after verifying a clean hosted run succeeds; it does not replace application compatibility tests for an upstream update.

Hosted Mac artifacts use ad-hoc signing and are not equivalent to persistently signed Maya releases or an upgradeable Mac feed. No signing key is copied to GitHub. A proper signed release still uses the existing Maya release process.

The lane builds Linux x64 server archives and macOS ARM64 DMG/ZIP artifacts afresh, with a smoke check for each. It retains workflow artifacts for 14 days, named with version, full source SHA and target. Each target carries `voice-release.json`, `SHA256SUMS`, and upstream notes followed by `## Voice Fork`. The descriptor records the source/upstream pins, registered database migration head, orchestration protocol version, final-byte SHA-256/size, target and experimental trust state. Per-target descriptors are build evidence, not a combined public release manifest or update feed. Publication would need a separately reviewed aggregation step that rejects mismatched versions/source pins, plus explicit approval. No release, tag, npm publication, deployment or installation runs here.

The inherited upstream release pipeline remains gated. This lane does not pass the inherited `--skip-build` flag, which the fork packager correctly refuses. Native build success, artifact retention, macOS trust, real installation/update and rollback must be evidenced separately; a checksum or successful unit test is not that proof. Hosted runner availability and macOS billing limits must be checked on the account.

## Signed upstream updates (disabled until configured)

`voice-upstream-watch.yml` checks the latest stable release every six hours when installed on the default branch and enabled. It rejects drafts, prereleases, moved tags, commits outside upstream `main`, and releases not descending from the accepted pin. Main commits alone do not trigger work. The sender performs release verification; an ordinary scheduled task must repeat it before changing code. Release notes remain untrusted data.

Precreate and verify the `voice-automation` environment before registering/running the workflow, even before storing secrets; otherwise GitHub can implicitly create an unprotected environment. The `voice-automation` environment must restrict deployments to the exact default branch (branch rule only, no tags). Verify the saved deployment policy before adding secrets; an environment name or pinned checkout alone does not protect secrets from modified branch workflows. Keep default-branch workflow changes owner-authorized and reviewed. Required environment reviewers, if configured, pause every poll; no per-run reviewer is required by this personal-fork policy. Honor existing enforced protections, and keep the exact default-branch environment restriction before adding secrets.

The protected `voice-automation` environment must set `VOICE_UPSTREAM_SOURCE_SHA` to a reviewed full sender commit containing the bounded release-response fix and the currently accepted upstream pin. Advance this SHA after every accepted upstream update; otherwise the sender keeps proposing an already accepted release. The workflow checks out that immutable source, independently of the receiver's approved worktree base. An unset source SHA produces a notice and skips checkout/poll/delivery; a malformed nonempty SHA fails closed. A manual send request while delivery is disabled produces a notice. Manual dispatch on the default branch defaults to a read-only poll; `send_webhook: true` requests delivery only while `VOICE_UPSTREAM_WATCH_ENABLED` is `true`. Set that switch in the `voice-automation` environment, without a repository/organization variable of the same name. The send step evaluates it after environment variables are available, for both scheduled and manual runs; unset or false disables all delivery. Read-only manual polling remains available. Public GitHub API requests are unauthenticated and can hit shared-runner rate limits; an HTTP rate-limit failure stops the run without delivery and must not be reported as a successful no-op. GitHub must first register the workflow on the default branch before branch dispatch or scheduled runs are available. An unchanged latest release is a successful no-op, not an end-to-end launch test; do not reset the accepted pin to manufacture a candidate.

Use an ordinary signed scheduler webhook, with `threadId: null`, `threadMode: "new_thread"`, an explicit Voice `projectId`, stored `modelSelection` (including provider options), `runtimeMode: "full-access"`, and `interactionMode: "default"`. Configure these through the normal authenticated scheduler Settings/RPC. The MCP `schedule_task` tool inherits caller model/modes and chooses its own default worktree base; it cannot express the complete configuration. No custom receiver, private binding file or server automation flag is used.

Set `workspaceStrategy` to an isolated `worktree`, with an explicit immutable `baseRef` and `startFromOrigin: false`. The fork's generic `approvedBase` and `enforceNoSetupScripts` guards remain available; these are additions to pinned upstream, not standard upstream capabilities. Model settings are saved on the task, not reread from project defaults for every delivery. Review them when changing project defaults.

Keep delivery disabled. This removal is blocked for activation until sender-side duplicate handling is agreed and verified. Upstream replay keys persist for seven days; relay delivery IDs persist for 48 hours. A release identity template such as `{{body.upstream}}:{{body.tag}}:{{body.sha}}` avoids the sender's fresh UUID on each poll, but still expires and does not enforce permanent tag claims, one active update, or a rolling 24-hour launch limit. Task prompt instructions run after model allocation and cannot supply those guarantees. Do not enable the existing sender against a new ordinary task on the strength of prompt instructions alone.

The existing dependency-free `voice-upstream-coordinator.ts` claim/verification helpers remain outside the server for offline checks and possible sender/task use. They are not automatically called by standard webhooks. `scripts/voice-upstream-poll.ts` retains stable-release, tag, ancestry, publication and accepted-pin checks plus HMAC signing. An ordinary task can rerun the read-only poll before implementation; checks after launch do not prevent allocation to an invalid or duplicate candidate. Sender reconciliation after an uncertain delivery must fail closed rather than blindly retry.

The task can implement the update, resolve conflicts, review migrations, test, request the authorized council, merge the exact reviewed head and request build-only artifacts using ordinary tools. These are task instructions with ordinary permissions, not durable scheduler enforcement. Reuse `voiceUpgradeWorkerPrompt` when preparing the task; it retains the exact-head council, merge/check and no-deployment rules. No task is created or migrated by this source change.

Retired action records are rejected on decoding rather than silently converted to prompt tasks. Remove old action tasks through normal administration before installing this removal: they would otherwise also prevent task listing. Reconcile their claims before explicitly creating a paused ordinary replacement. No database downgrade, userdata rename or automatic state conversion is needed. Existing disabled activation receipts and private bindings are historical evidence, not commands to execute for this path.

### Retired Pi automation

Old private bindings are unused; they cannot activate ordinary scheduler tasks. Old clean-constrained launches/replays and provider sessions are rejected. Queued work and restart continuations whose thread history contains a clean constraint fail before provider startup; create a new ordinary thread explicitly instead of resuming them unrestricted. Historical constraint decoding remains only for retirement compatibility. Normal upstream Pi and stored provider-secret loading remain available. Pause old scheduler tasks and reconcile any old active claim before configuring an ordinary task.
